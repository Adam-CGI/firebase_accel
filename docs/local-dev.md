# Local Development

This project uses Vite for frontend development and Firebase Hosting for deployment. You have two good local flows. The repo also includes a minimal Firebase init that auto-connects SDKs to local emulators while in dev.

## 1) Fast dev with Vite (HMR)
- Start Vite dev server:

```bash
npm run dev
```
- App runs at http://localhost:5173 with hot module reload.

Use this mode for day-to-day UI work. If/when you add Firebase client SDKs (Auth, Firestore, etc.), connect those SDKs to the local emulators (see the notes below) while still using Vite for HMR.

## 2) Production-like preview via Firebase Hosting Emulator
- Build the app and serve it using the Hosting emulator:

```bash
npm run preview:hosting
```
- This builds to `dist/` and serves the exact production bundle at http://localhost:5000
- The Emulator UI (dashboard) is at http://localhost:4000

If you prefer to start the hosting emulator without building each time (e.g., `dist/` already exists):

```bash
npm run emulators
```

## Firebase SDK & Emulators (Auth/Firestore/Storage)
We ship a minimal initializer at [src/firebase.js](../src/firebase.js).

1) Create a `.env.local` based on `.env.example` and fill in your Firebase Web App config (from Firebase Console → Project Settings → Your apps → Web app):

```bash
cp .env.example .env.local
```

2) Import and use from your app code (e.g., in `src/main.jsx` or a feature module):

```js
import { app, auth, db, storage } from './firebase';
```

3) Start all emulators when developing services:

```bash
npm run emulators:all
# in another terminal
npm run dev
```

Emulator ports (configurable in `firebase.json`):
- Auth: http://127.0.0.1:9099
- Firestore: 127.0.0.1:8080
- Storage: 127.0.0.1:9199
- Hosting: http://localhost:5000
- Emulator UI: http://localhost:4000

## Prerequisites
- Node.js and npm
- Firebase CLI: either install globally or use `npx` (the scripts use `npx` so a global install is optional)

Global install (optional):
```bash
npm install -g firebase-tools
```

Authenticate once (if needed):
```bash
npx firebase login
```

The default project is set in `.firebaserc` and used for emulator context.

## Adding service emulators later (overview)
If you add more Firebase client SDKs in the future and want to develop against local emulators:

1) Expand `firebase.json` to include the emulators you need, for example:
```json
{
  "emulators": {
    "auth": { "port": 9099 },
    "firestore": { "port": 8080 },
    "storage": { "port": 9199 },
    "hosting": { "port": 5000 },
    "ui": { "enabled": true, "port": 4000 }
  }
}
```

2) In your app’s Firebase init code, connect SDKs to emulators during local dev. Example (React/Vite):
```ts
import { initializeApp } from 'firebase/app';
import { getAuth, connectAuthEmulator } from 'firebase/auth';
import { getFirestore, connectFirestoreEmulator } from 'firebase/firestore';
import { getStorage, connectStorageEmulator } from 'firebase/storage';

const firebaseConfig = { /* your config */ };
const app = initializeApp(firebaseConfig);

if (import.meta.env.DEV) {
  const auth = getAuth(app);
  connectAuthEmulator(auth, 'http://127.0.0.1:9099');

  const db = getFirestore(app);
  connectFirestoreEmulator(db, '127.0.0.1', 8080);

  const storage = getStorage(app);
  connectStorageEmulator(storage, '127.0.0.1', 9199);
}
```

3) Start the emulators alongside Vite:
```bash
npx firebase emulators:start
npm run dev
```

You can also wire up a single script using a process runner like `concurrently` if desired.

## Notes
- Vite dev server is best for UI iteration (HMR). Use the Hosting emulator when you want to test the production bundle locally.
- The Hosting emulator serves `dist/` which is generated by `npm run build`.
